# Модульное тестирование класса Burger

Проект содержит автоматизированные модульные тесты для проверки бизнес-логики класса `Burger` в приложении на Java. Тестирование охватывает управление булочками и ингредиентами, изменение порядка ингредиентов, расчёт стоимости бургера и формирование чека.

Тесты написаны с использованием JUnit 4 и Mockito. Для анализа покрытия исходного кода тестами используется JaCoCo.

## 🛠 Технологический стек

* **Язык программирования:** Java 11
* **Сборщик проектов:** Maven
* **Тестовый фреймворк:** JUnit 4 (`4.13.2`)
* **Мокирование зависимостей:** Mockito (`5.23.0`)
* **Анализ покрытия кода:** JaCoCo (`0.8.15`)
* **Запуск тестов:** Maven Surefire Plugin (`3.2.5`)

## 🏗 Архитектура проекта и подходы к тестированию

Проект организован с разделением исходного кода и тестов в соответствии со стандартной структурой Maven.

* **Production Layer:** классы `Burger`, `Bun`, `Ingredient`, `IngredientType` и `Database`, реализующие логику работы с бургером и его составляющими.
* **Unit Test Layer:** отдельные тестовые классы для проверки поведения методов `Burger`. Каждый тест проверяет конкретный сценарий работы программы.
* **Mocking:** использование Mockito для создания тестовых объектов `Bun` и `Ingredient`, настройки возвращаемых значений и изоляции тестируемой логики от реальных объектов.
* **Parameterized Testing:** использование `@RunWith(Parameterized.class)` и `@Parameters` из JUnit 4 для проверки расчёта стоимости бургера с различным количеством ингредиентов и разными ценами.
* **Code Coverage:** интеграция JaCoCo с Maven для формирования отчёта о покрытии исходного кода тестами.

## 🧪 Структура тестов и покрытие

### `BurgerTest` — проверка основных методов класса Burger

* **`setBuns()`** — проверка установки булочки и сохранения переданного объекта.
* **`addIngredient()`** — проверка добавления ингредиента в список.
* **`removeIngredient()`** — проверка удаления ингредиента по индексу и корректности оставшегося списка.
* **`moveIngredient()`** — проверка перемещения ингредиента на другую позицию и сохранения ожидаемого порядка элементов.
* **`getPrice()`** — проверка расчёта итоговой стоимости бургера с учётом стоимости двух булочек и всех добавленных ингредиентов.
* **`getReceipt()`** — проверка формирования чека, содержащего названия булочек, типы и названия ингредиентов, а также итоговую стоимость.

### `BurgerParameterizedTest` — параметризованное тестирование стоимости

Проверка метода `getPrice()` на различных наборах входных данных:

* Бургер без ингредиентов.
* Бургер с одним ингредиентом.
* Бургер с несколькими ингредиентами.
* Бургеры с различными ценами булочек и ингредиентов.
* Проверка корректности суммирования стоимости всех составляющих.

Параметризованные тесты позволяют проверять несколько сценариев одним тестовым методом, уменьшая дублирование кода.

## ▶️ Запуск тестов

Для запуска всех тестов из корня проекта выполни команду:

```bash
mvn clean test
```

Команда очищает результаты предыдущей сборки, компилирует исходный и тестовый код, запускает тесты с помощью Maven Surefire и формирует отчёт JaCoCo.

## 📊 Отчёт о покрытии кода

После выполнения тестов HTML-отчёт JaCoCo доступен по пути:

```text
target/site/jacoco/index.html
```

Открой файл в браузере, чтобы посмотреть показатели покрытия классов, методов, строк и ветвей, если они присутствуют в анализируемом коде.
