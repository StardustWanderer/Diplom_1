# Diplom_1 — Юнит-тестирование класса Burger

## О проекте

Проект посвящён юнит-тестированию Java-приложения **Stellar Burgers**.

Основная задача — проверить бизнес-логику класса `Burger`, который управляет составом бургера, рассчитывает его стоимость и формирует чек.

Для написания юнит-тестов используются JUnit 4 и Mockito. JaCoCo применяется для анализа покрытия исходного кода тестами.

**Результат: 100% покрытия класса `Burger` по отчёту JaCoCo.**

## Технологический стек

- **Java 11** — язык программирования.
- **Maven** — управление зависимостями и сборка проекта.
- **JUnit 4.13.2** — написание и запуск юнит-тестов.
- **Mockito 5.23.0** — создание мок-объектов и настройка стабов.
- **JaCoCo 0.8.15** — анализ покрытия кода тестами.
- **Maven Surefire Plugin 3.2.5** — запуск тестов в рамках Maven.

## Объект тестирования

Основной объект тестирования — класс `Burger`.

Он содержит следующие методы:

| Метод | Назначение |
|---|---|
| `setBuns()` | Устанавливает булочку для бургера |
| `addIngredient()` | Добавляет ингредиент |
| `removeIngredient()` | Удаляет ингредиент по индексу |
| `moveIngredient()` | Перемещает ингредиент на другую позицию |
| `getPrice()` | Рассчитывает стоимость бургера |
| `getReceipt()` | Формирует текстовый чек |

Стоимость бургера рассчитывается по формуле:

`Стоимость = 2 × стоимость булочки + сумма стоимости ингредиентов`

## Подходы к юнит-тестированию

### JUnit 4

Для проверки поведения методов используются обычные и параметризованные тесты.

Тесты организованы по принципу **Arrange — Act — Assert**:

- **Arrange** — подготовка объекта и тестовых данных.
- **Act** — вызов тестируемого метода.
- **Assert** — проверка результата.

### Mockito: моки и стабы

Mockito используется для создания тестовых объектов `Bun` и `Ingredient`.

С помощью `when().thenReturn()` задаются контролируемые возвращаемые значения методов:

- `getPrice()` — для проверки расчёта стоимости;
- `getName()` — для проверки содержимого чека;
- `getType()` — для проверки отображения типа ингредиента.

Это позволяет изолировать логику класса `Burger` от реализации его составляющих и не зависеть от конкретных значений реальных объектов.

Для проверки операций со списком ингредиентов используются реальные объекты. Их состояние проверяется через содержимое списка после выполнения операции.

### Параметризованное тестирование

Для проверки метода `getPrice()` используется `@RunWith(Parameterized.class)` и аннотация `@Parameters` из JUnit 4.

Подготовлено пять наборов тестовых данных:

| Цена булочки | Цены ингредиентов | Ожидаемая стоимость |
|---:|---|---:|
| 100 | Без ингредиентов | 200 |
| 100 | 50 | 250 |
| 100 | 50, 30 | 280 |
| 200 | 100, 50 | 550 |
| 300 | 100, 200, 300 | 1200 |

Параметризация позволяет проверить расчёт стоимости при разном количестве ингредиентов и разных ценах без дублирования тестового метода.

## Структура тестов

### `BurgerTest` — проверка основных методов

- **`setBunsSetsCorrectBun()`** — проверяет, что бургер сохраняет переданный объект булочки.
- **`addIngredientAddsIngredientToList()`** — проверяет добавление ингредиента в список.
- **`removeIngredientRemovesIngredientByIndex()`** — проверяет удаление ингредиента по индексу и корректность оставшегося списка.
- **`moveIngredientChangesIngredientOrder()`** — проверяет перемещение ингредиента и сохранение ожидаемого порядка элементов.
- **`getPriceReturnsCorrectBurgerPrice()`** — проверяет расчёт стоимости бургера с несколькими ингредиентами.
- **`getReceiptReturnsCorrectReceipt()`** — проверяет формирование чека целиком, включая названия булочек, типы и названия ингредиентов, а также итоговую стоимость.

### `BurgerParameterizedTest` — параметризованная проверка стоимости

Метод `getPriceReturnsExpectedPrice()` запускается для пяти наборов входных данных.

Проверяются случаи:

- бургер без ингредиентов;
- бургер с одним ингредиентом;
- бургер с несколькими ингредиентами;
- разные цены булочек;
- разные сочетания цен ингредиентов.

Для сравнения числовых результатов используется допустимая погрешность `0.001f`.

## Покрытие кода

Для анализа покрытия используется JaCoCo Maven Plugin.

Плагин подключается к процессу тестирования через `prepare-agent`, собирает данные о выполнении кода и формирует HTML-отчёт с помощью цели `report`.

**Результат: класс `Burger` покрыт тестами на 100%.**

После выполнения тестов отчёт доступен по пути:

```text
target/site/jacoco/index.html
```

В отчёте можно посмотреть покрытие классов, методов, строк и инструкций, а также ветвей, если они присутствуют в коде.

## Запуск тестов

Для запуска проекта необходимы JDK 11 или выше и Maven.

Из корневой директории проекта выполни:

```bash
mvn clean test
```

Команда:

1. Очищает результаты предыдущей сборки.
2. Компилирует исходный и тестовый код.
3. Запускает тесты с помощью Maven Surefire.
4. Собирает данные о покрытии с помощью JaCoCo.
5. Формирует HTML-отчёт.
